# ТехМаркет туслах

Mastra + Gemini ашигласан agentic AI туршилтын төсөл. Зохиомол электроникийн дэлгүүрийн хэрэглэгчид үйлчлэх агент: бараа хайх, захиалга шалгах, цуцлах, тасалбар үүсгэх, мэдлэгийн сангаас хайж хариулах.

Сайт: https://mastra-support-agent.vercel.app

## Гол боломжууд

- **Tool calling** — агент дэлгүүрийн өгөгдлийн сантай 6 tool-оор ажиллана.
- **RAG (мэдлэгийн сан)** — `knowledge/` доторх баримтуудыг хэсэглэж, embedding-ээр утгаар нь хайна.
- **Human-in-the-loop** — захиалга цуцлах tool нь хүн «Зөвшөөрөх» дарах хүртэл ажиллахгүй.
- **Eval** — тест асуултуудаар агентыг автоматаар үнэлнэ (`npm run eval`).
- **Бодит цагийн самбар** — алхам бүрийн хугацаа, токены тоог чатын хажууд харуулна.
- **Хамгаалалт** — нэвтрэх код, хүсэлтийн тооны хязгаар.

## Бүтэц

- `src/lib/db.ts` — дэлгүүрийн SQLite өгөгдлийн сан, жишээ өгөгдөл
- `src/mastra/tools/shop-tools.ts` — агентын 6 tool (`cancelOrder` нь `requireApproval: true`)
- `src/mastra/agents/support-agent.ts` — агентын тодорхойлолт, заавар
- `src/app/api/chat/route.ts` — чатын API, агентын алхам бүрийн цаг болон токеныг урсгалд нэмдэг
- `src/app/page.tsx` — чатын хуудас, зөвшөөрлийн товч, нэвтрэх кодын дэлгэц
- `src/app/agent-panel.tsx` — агентын ажиллагааг бодит цагт харуулах самбар
- `knowledge/*.md` — мэдлэгийн сангийн эх баримтууд
- `scripts/ingest.mts` — баримтыг хэсэглэж embedding хийгээд `src/knowledge/index.json` үүсгэнэ
- `src/lib/knowledge.ts` — индексийг libSQL вектор санд ачаалж, хайлт хийнэ
- `scripts/eval.mts` — үнэлгээний тестүүд
- `src/lib/guard.ts` — нэвтрэх код, хүсэлтийн хязгаар

## Ажиллуулах

```bash
npm install
cp .env.example .env.local   # GOOGLE_GENERATIVE_AI_API_KEY-г бөглөнө
npm run dev
```

Түлхүүрийг https://aistudio.google.com/apikey -аас авна. Загварыг `GEMINI_MODEL` хувьсагчаар сольж болно (жишээ нь `google/gemini-3.5-flash-lite`).

## Мэдлэгийн сан (RAG)

`knowledge/` доторх markdown файлыг засах эсвэл шинээр нэмсний дараа индексийг дахин үүсгэнэ:

```bash
npm run ingest
```

Скрипт баримтыг `##` гарчгаар хэсэглэж, хэсэг бүрийг Gemini-ийн `gemini-embedding-001` загвараар вектор болгоод `src/knowledge/index.json`-д хадгална. Энэ файл git-д ордог тул сервер ажиллах үед зөвхөн хэрэглэгчийн асуултыг вектор болгодог.

## Үнэлгээ (eval)

```bash
npm run eval                 # бүх тест
npm run eval -- --only=rag   # нэр нь "rag"-аар эхэлсэн тестүүд
npm run eval -- --limit=3    # эхний 3 тест
```

Тест бүр агентыг нэг удаа ажиллуулж, зөв tool дуудсан эсэх болон хариунд хүлээсэн мэдээлэл байгаа эсэхийг кодоор шалгана. Тестүүд `data/eval` хавтас дахь тусдаа өгөгдлийн сан ашигладаг. Тест бүр 2-3 LLM хүсэлт зарцуулна. Загвар эсвэл агентын зааврыг сольсны дараа ажиллуулж дүнг харьцуулна.

## Хамгаалалт

- `ACCESS_CODE` тохируулбал сайт нэвтрэх код асууна. Тохируулаагүй бол нээлттэй.
- `CHAT_LIMIT_PER_MINUTE` (анхдагч 8): нэг IP-ээс минутад илгээх чатын хүсэлт.
- `CHAT_LIMIT_PER_DAY` (анхдагч 200): бүх хэрэглэгчийн өдрийн нийт хүсэлт.

Тоолуур серверийн санах ойд байдаг тул Vercel дээр instance бүр тусдаа тоолно: хязгаар ойролцоо үйлчилнэ.

## Анхаарах зүйл

Vercel дээр SQLite файл `/tmp`-д байрладаг тул өгөгдөл түр зуурынх: сервер дахин асахад анхны төлөвтөө орно. Зөвшөөрөл хүлээж буй ажиллагааны төлөв мөн тэнд хадгалагддаг тул удаан хүлээсний дараа «Зөвшөөрөх» дарахад алдаа гарч болно.
